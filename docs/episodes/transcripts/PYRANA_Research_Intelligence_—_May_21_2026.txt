HOST_A: Okay so explain temporal semantic caching like I'm new to this. Because I get semantic — embeddings, vector similarity, you've heard this query before. What's the temporal part?
HOST_B: So they bucket every incoming query into one of four time-sensitivity categories before it even hits the cache. Volatile means live state — inventory levels, current sensor readings — and those bypass the cache entirely. Static means there's no time dependence — "what's the capital of France." Anchored means there's a fixed time window — "sales for Q1 2026" — and you can only hit a cached answer if it covers a compatible window. And Relative is stuff like "yesterday" or "last week" that you resolve to a concrete window first, then treat as Anchored.
HOST_A: So the cache is allowed to say "I have a hit semantically, but the time window doesn't overlap, so I'm going to miss anyway."

HOST_A: Wait, the combined number is worse?
HOST_B: It's worse on that specific metric but it's evaluating a harder, more realistic distribution. The point is more that naive semantic caching is dangerous, and even careful temporal caching is still probabilistic. You're going to be wrong on some cache decisions.

HOST_A: Good. Paper two — AgentCo-op from CMU. Plain English first.
HOST_B: Right now, when we build a workflow for a customer, we hand-write a YAML config — these are the agents, this is how they're wired, here's the tool manifest. AgentCo-op says: don't do that. Best results on four of six benchmarks, lower per-task token cost than search-based competitors.
HOST_A: Synthesis by retrieval rather than search. Unpack that — what's the contrast?
HOST_B: So there are two schools. Search-based — AFlow is the canonical example — treats workflow design as an optimization problem. You explore a space of possible graphs, you score them, Monte Carlo tree search, you iterate. Powerful but expensive and you need a scalar reward signal to optimize against. Retrieval-based says: I have a library of known-good skills and tools. Given the task, I'll fetch the relevant ones and compose them into a graph. No global search.
HOST_A: And the composition isn't random — it's typed.
HOST_B: That's the key idea. Every node in the graph — every agent role — has typed input and output schemas. The edges aren't just "this calls that," they're "this produces an artifact of type X, that consumes an artifact of type X." Interface alignment is enforced at synthesis time, not discovered at runtime when something blows up.
HOST_A: That sounds a lot like what our tool manifest already does, informally.
HOST_B: It does. The @tool decorator already declares inputs and outputs. We just don't treat those as first-class compositional contracts the way AgentCo-op does. We treat them as documentation for the LLM.
HOST_A: There's also a repair piece I want to get to.
HOST_B: Yeah, this is nice. Execution happens, and a reviewer agent watches the signals — tool errors, validation failures, budget overruns, interface mismatches. HOST_A: Steel man?

Tool Guide modifies how tools are presented to the planner.
