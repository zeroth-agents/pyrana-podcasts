HOST_A: Okay wait, "oracle" — explain that.
HOST_B: An oracle, in testing, is the thing that tells you whether the result was right. So if I run my function and it gives me back a number, the oracle is the assertion that says "this number should equal 42." Without an oracle, you're just running code and confirming it didn't crash. That's not a test, that's a smoke check — hence the title.
HOST_A: And they built a taxonomy of how strong or weak the oracle is.
HOST_B: Eight categories. Five weak tiers from W1 — literally no assertion — up through W5, which is snapshot tests. Then three strong tiers: S1 is checking a value equals what you expect, S2 is checking the right kind of error gets thrown, S3 is multiple strong checks combined. They built it through open coding on 384 samples, got a Cohen's kappa of 0.77 between human raters — that's solid agreement — and then applied it via regex pattern matching across all 86,000 patches.
HOST_A: And the agents vary, right? It's not all uniformly bad?
HOST_B: Big variance. On newly created test files, strong-oracle rate ranges from 18% for OpenAI Codex up to 67% for Claude Code. So Claude Code is roughly three and a half times more likely to write a test that actually tests something than Codex is.

HOST_A: That's a huge gap. How is the tree actually structured?
HOST_B: It's a directed acyclic graph — basically a hierarchy with some shared nodes. Top levels are broad clinical capabilities. Leaves are atomic Boolean functions that return zero or one given the context and the response. A physician panel grows the tree iteratively: they look at real user queries, find places where current leaves can't deterministically verify the answer, and add the minimum new leaves needed. There's a complexity penalty so it doesn't sprawl. Weights propagate top-down with equal splits at every branch, so nobody hand-tunes weights.
HOST_A: And the adaptive router?
HOST_B: At query time, a router picks just the relevant subset of rubrics to actually run, so you're not evaluating every single leaf on every query. They explicitly treat the router as boring infrastructure — the clinical reliability lives in the expert-curated leaves, not in the routing.
