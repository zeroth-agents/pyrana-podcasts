Today's four papers share a single anxiety: agent systems that quietly degrade as they scale. The episode traces two failure vectors — skill libraries that bloat and drift over time, and long-context agents that waste tokens re-orienting themselves on every turn — and examines the runtime primitives that could contain both problems. Listeners come away with concrete vocabulary for the "reasoning vs. bookkeeping" split and a clearer picture of where structured formalism pays off versus where it adds authoring cost.

For PYRANA, the overlap is direct. The @tool catalog is exactly the skill library that Library Drift warns about, and the Formal Skill paper is effectively a draft spec for what a governed tool registration should look like — schema, executor, lifecycle hooks, state. Meanwhile, PEEK maps almost one-to-one onto MessageBuilder: the Distiller/Cartographer/Evictor architecture is a concrete blueprint for how accumulated CxU context should be summarized and pruned across agent turns rather than rebuilt from scratch each time.

Papers covered:

  • Formal Skill: Programmable Runtime Skills for Efficient and Accurate LLM Agents — Replace prose skill descriptions with schema-plus-executor objects; achieves competitive results with ~48% fewer tokens.
  • PEEK: Context Map as an Orientation Cache for Long-Context LLM Agents — Cache a compact, updatable orientation map so agents stop re-deriving context state on every turn.
  • A Methodology for Selecting and Composing Runtime Architecture Patterns for Production LLM Agents — Provides principled vocabulary and selection criteria for agent runtime architectural primitives.
  • Library Drift: Diagnosing and Fixing a Silent Failure Mode in Self-Evolving LLM Skill Libraries — Names and characterizes the gradual rot that unbounded skill libraries suffer as new entries conflict with old ones.

Takeaways for our platform:

  • Audit the five highest-token-cost tools in the @tool catalog and pilot Formal Skill structure — schema, executor, lifecycle hooks — there first; formalize selectively where amortization actually moves cost, not uniformly across all tools.
  • Treat PEEK's Distiller/Cartographer/Evictor loop as a concrete design target for MessageBuilder: CxUs should be priority-ranked and evicted against a fixed token budget rather than accumulated unbounded across agent turns.
  • Apply Library Drift's diagnostic criteria to the @tool catalog now, before the library is large enough for drift to be invisible — establish a conflict-detection pass as part of the tool registration governance pipeline.
